1 · What this is, in one paragraph

PR #3 shipped micro-agents as decorative state objects — 2–4 spheres orbiting each leaf on the dashboard, doing no real work. The cache-network beneath them is real and wired. This design makes micros real as read-side context-gatherers inside the audit-run testers-pool: cheap (Haiku) read-only sub-sessions summarize a tester's input targets, those summaries fold into the tester's prompt, and the expensive (Opus) tester reads the compact summary instead of re-reading raw sources. Every micro call rides the existing content-addressed cache, so identical sub-jobs across testers are free. The whole thing is instrumented so its first real run answers one question: does the cost model actually pay? — which gates the more ambitious write-side v2.

The one-line invariant. v1 saves money iff, across the pool with cache hits counted:
Σ(folded Opus input + Haiku input) < Σ(baseline raw Opus input).
Input tokens only (near-deterministic) → a single before/after diff is honest, no N-run statistics.

4 · Measurement & the v2 decision gate

v1's product is evidence, not savings. Two risks are promoted to first-class metrics: compression might be nominal (Risk 1); testers might re-read raw anyway (Risk 2).

MetricFormulaTells us
Net input-token delta (headline)Σ(folded Opus in + Haiku in) − Σ(baseline raw Opus in)Did v1 pay?
Dedup ratecache hits / total micro callsCross-tester reuse
Re-read rateredundant raw Reads / folded targetsWhy it paid or didn't (Risk 2)
Compression ratioΣ summary tokens / Σ raw bytesSummaries real or nominal (Risk 1)

Baseline via a new --no-micros flag (additive, mirrors --no-cache): run once off, once on, diff micro-metrics.json.

OutcomeVerdict
Net delta < 0 and re-read rate lowRead-side pays → scope write-side v2
Net delta ≥ 0 but re-read rate highSabotaged by re-reads, not disproven → fix steering, re-measure
Net delta ≥ 0 and low re-read and poor compressionDoesn't pay here → do NOT build v2 (cheap kill signal)
Known limitation. The audit pool proves read-side is safe and measures dedup well, but testers do precise assertion work that resists summarization — so the pool may under-show compression vs. broad-synthesis cultivate leaves. A weak compression number here means "audit testers are the hardest case," not "read-side fails." The re-read metric disambiguates.

5 · Failure isolation

Governing rule: a micro failure never fails or degrades the tester — it falls back to baseline (reads raw itself).

FailureHandlingEvent
Worker throws / times outDrop summary; tester re-reads that raw targetmicro.work_failed
Empty / garbage summaryTreated as no-summary (no quality check in v1 — v2's reviewer)micro.work_empty
derivePlan → 0 sub-jobsSkip fan-out; tester runs as today; zero overheadmicro.plan_empty
Over USD capMicros draw from tester's existing maxBudgetUsd; skip if exceedingmicro.budget_skipped

Structural payoff of read-side: read-only tools → a failed/interrupted micro leaves zero artifacts and zero git state. Nothing to roll back.
