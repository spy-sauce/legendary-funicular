Maui-as-Product — v3 (terminology key + curated promotion)

Resolved: cultivations run privately by default; becoming a reusable biome requires an approval gate. The bus stays curated.

🗝️ Terminology — read this first

Nutrient — a unit of work/data that flows on the bus. Here: an intent (what the user asked) or a result coming back.
Biome — any participant plugged into the bus. A front door, a capability, a RAG — all biomes. Think: "a node that can send/receive nutrients."
The Bus — peer-to-peer message fabric. No central boss. Every biome talks to it in one shared protocol.
Capability — something that DOES work: a Frank service, a RAG, an MCP tool. ~789 of them exist already.
Adapter — thin shim that makes a whole CLASS of capabilities (all HTTP services, all RAGs…) speak bus. Written once per protocol, not per capability.
Cultivation — a Mycelium run that decomposes a big goal into many parallel agents (leaves) and composes their output. The "build-anything" path.
Triage — the sizing step: is this a cheap lookup, a single capability, or a full cultivation? Decided once, up front.
Promotion — the GATED path by which a proven cultivation output becomes a permanent, reusable capability-biome. Not automatic.

2 · Triage — size & ROUTE (never composes)

① Lookup ≈ $0

Single capability / model call / RAG query. Answer inline, done.

② Composed task

2+ capabilities, KNOWN shape → routes to a contract-bound Mycelium agent. Pre-defined first, dynamic later. Agent composes, not triage.

③ Build → spend-gate

Novel goal, decompose from scratch → cultivation. Over threshold → texts "build X, ~$Y, go?", waits.

Triage picks the tier and hands off. Composition is ALWAYS owned downstream (agent or cultivation), never by triage.

▼   the "build-anything" path lands here · leaves reach back UP to capability biomes
4 · Mycelium engine — owns ALL composition · invoked by hand OR auto-triggered

② Tier-2 contract-bound agent

Fixed-shape composition via NUTRIENTS contract. No decomposition. Cheap, predictable, testable. v1 = pre-defined; dynamic later.

③ Tier-3 cultivation

plant→freeze→cultivate→harvest. Novel goal decomposed from scratch. Owns fan-out/CommitQueue. NOT automatically a biome.

🍄 Leaves/steps call capability-biomes

Toolset = capability-biomes on the bus. Where composition + the fleet finally meet.

CLI is the engine's interface, NOT a human-at-terminal requirement. Same build cycle whether you type `mycelium …` or a routed request auto-triggers it. Spend-gate + promotion gate make headless invocation safe.

Resolved: not every cultivation joins the organism. A user could build nonsense — it stays private until it earns promotion. ↓

▼   only IF it proves useful
5 · Promotion — gated path from cultivation → permanent biome

🍄 Cultivation output

A working fruit. Lives privately. Reusable only by re-running.

→

🚦 Approval gate

Operator (or policy) reviews: useful? safe? non-nonsense? Worth keeping?

→

🔌 Wrapped as adapter

Gets a bus adapter + cap-reg entry. Now discoverable.

→

♻️ Permanent capability-biome

Joins layer 3. Future triage can route to it directly — no rebuild.

The bus stays CURATED. Cultivations produce candidates; only approved ones become permanent. Nonsense never auto-joins.
