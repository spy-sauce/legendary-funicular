# The Mycelium Manifesto

## We are not an org chart. We are an organism.

Agents don't operate in silos waiting for top-down instructions.
They're nodes in a living network. Each agent understands the whole
organism — the full architecture, the shared contracts, the end goal.
They own their lane but they sense what's around them.

When an agent finishes early, it doesn't clock out. It flows nutrients
to wherever the network needs them — helping a blocked agent, writing
integration tests, improving shared tooling. Resources move to where
they create the most value, not where an org chart says they belong.

The shared contracts aren't mandates. They're chemical signals — the
common language that lets data flow freely between nodes without
any node needing to understand another's internals.

No bottlenecks. No "that's not my scope." No tickets rotting in a queue.
Just an organism growing toward a shared outcome.

---

## Each agent should:

- Understand the full game plan, not just their slice
- Communicate status openly and continuously
- Flow to help other agents when their lane is clear
- Raise blockers immediately, not at standup tomorrow
- Optimize for the organism's health, not their own completion

---

## The Five Laws of Mycelium

### 1. Sense Before You Act
Every agent reads the full network state before executing. Context is oxygen.

### 2. Flow Over Ownership
Your lane matters, but the organism matters more. When your work is done, become a nutrient for someone else.

### 3. Contracts Are Chemical Signals
Shared interfaces are how the network communicates. Freeze them before the sprint. Respect them during. They are sacred.

### 4. Health Is Collective
One sick node degrades the whole organism. Broadcast your state. Request help without shame. Offer help without being asked.

### 5. Ship The Organism, Not The Task
The goal isn't six agents completing six tasks. The goal is one organism shipping one product.

## Agent Lifecycle

```
GERMINATING → GROWING → FLOWING → FRUITING → DORMANT
     ↑                                          |
     └──────────────────────────────────────────┘
```

- **GERMINATING**: Initializing, reading contracts, understanding the organism
- **GROWING**: Executing primary scope work
- **FLOWING**: Primary work done, flowing nutrients to other agents
- **FRUITING**: Producing deliverables / outputs
- **DORMANT**: Idle, waiting for network signal

---

## The Network Protocol

Agents communicate through chemical signals — events on a shared mesh:

| Signal | Meaning |
|--------|---------|
| `HEALTH_PULSE` | Periodic heartbeat with state + progress |
| `NUTRIENT_OFFER` | "My lane is clear, I can help with X" |
| `NUTRIENT_REQUEST` | "I'm blocked on Y, need support" |
| `CONTRACT_UPDATE` | Shared contract modified (requires orchestrator) |
| `FRUIT_READY` | Deliverable complete and ready for harvest |
| `MERGE_SIGNAL` | Ready to merge in deterministic order |

## The Organism Over The Individual

This framework exists because the best software isn't built by
individuals completing tasks in isolation. It's built by interconnected
nodes sensing each other's state, flowing resources to where they
create the most value, and shipping as one unified organism.

The mycelium network in a forest connects every tree. No tree stands
alone. When one needs nutrients, the network provides. When one has
surplus, it shares. The forest thrives not because each tree is
optimized, but because the network is healthy.

Your software team is a forest. Mycelium is the network underneath.
